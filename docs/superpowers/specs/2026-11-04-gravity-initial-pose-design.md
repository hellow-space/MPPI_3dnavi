# 重力基准与手动地图对齐

用户已授权修正初始化脚本：手动点击确定地图位置和朝向，水平基准不再由点击瞬间的机身姿态定义。保留 FAST-LIVO 完整三维运动；不修改外部工作区、滤波器、Nav2 行为树或里程计接口。

在 `feat/location` 当前工作区实现。现有脚本无重力输入，当前 FAST-LIVO 重力对齐关闭且没有重力向量话题，采用 `/livox/imu` 静止窗口的比力方向，经时间对齐的 TF 转到 camera_init，建立固定向上方向。兼容加速度以 g 或 m/s² 表示，只用方向及相对稳定性。

使用约 1 s 数据、至少 20 样本，角速度 ≤0.08 rad/s、加速度模相对标准差 ≤3%、方向偏离均值 ≤2°；再检查同期 TF 位移 ≤0.02 m、旋转变化 ≤2°。这些为初始保守默认值，可通过参数调整。TF 与原始数据年龄最多 0.5 s，配对误差最多 0.05 s。运动或时间异常时拒绝初始化并说明原因，不退回机身水平假设。

初次对齐将该向上方向旋转到 map Z，再按底盘水平投影计算 yaw 修正和 x/y 平移。初始 base 高度参数默认 0 m，只定义高程零点，不声称是真实地面高度。后续手动定位保留已确定的水平与高度基准，只更新 x/y/yaw。检测到时钟倒退时清除初始化；提供显式 reset 服务用于 FAST-LIVO 重启等无法可靠自动识别的原点重置。

校验消息 frame、时间、有限数值和四元数，TF 缺失时明确拒绝。保留当前固定变换的 10 Hz 动态发布方式，避免混入发布策略变更；重定位后需要用户在停止导航时清理受影响的地图历史。脚本本轮不自动取消目标或清地图。

方案比较：仅修原有矩阵无法独立恢复水平；改外部 FAST-LIVO 重力对齐需要另仓库分支和地图基准联调；原始 IMU + TF 可在本分支完成，代价是初始化必须有健康静止数据。用户已同意的目标为修初始化，具体数据来源是本轮实现选择。

验证：机身带俯仰但地面水平；已倾斜 camera_init；重新点击不改变水平/高度；运动、旧数据、无 TF、错误 frame、无效四元数不建立对齐；ROS 隔离域内验证订阅、输出和 reset。不得将离线结果声称为实机转圈修复。
