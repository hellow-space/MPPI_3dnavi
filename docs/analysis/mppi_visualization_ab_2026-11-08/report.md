# MPPI 可视化开关实测：2026-11-08

用户授权自动启动导航、选择起终点并做可视化 A/B 对照。按要求保持扫描链路和时间戳代码不变。

## 测试方法

- 运行现有 `scripts/start_navigation_height_jump.sh`。雷达、LIO 和 CuPy 高程图保持运行。
- 起点采用重新初始化前的实测 map 位姿：x=0.6388、y=-0.2537、yaw=-2.2320 rad。
- 目标：x=0.1794、y=-1.6816、yaw=-1.8820 rad。直线距离 1.5 m；候选走廊按半径约 0.8 m 检查静态地图空闲格。
- ComputePathToPose 成功，生成 59 个路径点，实际折线路径长度 1.510 m。四轮采用同一目标。
- 测试顺序 ON、OFF、OFF、ON，每轮新建 NavigateToPose 目标，预热 2 秒、采样 8 秒后取消。四轮都以 CANCELED（状态 5）结束，没有等到进展超时或执行恢复。
- 仅动态切换 `FollowPath.visualize`；每次均读回确认。采样规模始终 batch_size=1000、time_steps=56、model_dt=0.05，HeightJumpCritic 始终启用。
- 临时 LD_PRELOAD 计时钩子调用原库函数、原样返回结果和异常，只测量 `MPPIController::computeVelocityCommands` 与 `Optimizer::evalControl` 的 steady-clock 耗时。正式测试前在隔离域 198 用已有诊断程序验证钩子捕获了 70 次 evalControl。控制阶段计时包括路径处理、锁等待、优化器和可视化；不能把两个阶段相减视为纯 CPU 自耗时的精确分解。
- 采样器仅订阅轻量速度、路径、原始字节轨迹消息与日志。计时和观察程序有额外开销，两组采用同样方法；观察器单核 CPU 约 38～45%。

## 合并结果

| 指标 | 可视化开启 | 可视化关闭 |
|---|---:|---:|
| 有效控制调用数 | 322 | 323 |
| 控制函数平均耗时 ms | 24.33 | 12.71 |
| 控制函数 P95 ms | 35.93 | 20.47 |
| 控制函数 P99 ms | 41.86 | 25.59 |
| 控制函数最大耗时 ms | 47.93 | 35.30 |
| 优化器平均耗时 ms | 12.52 | 12.47 |
| 优化器 P95 ms | 20.09 | 20.12 |
| 超过 50 ms 的控制调用 | 0 | 0 |
| 最终速度 Hz | 20.08 | 20.07 |
| 轨迹消息数 | 322 | 0 |

关闭可视化后，控制函数平均耗时下降 47.8%，减少 11.62 ms。优化器平均约 12.5 ms，基本相同。差异主要位于优化器之外的可视化路径，不能解释为减少了轨迹采样或关闭了高程检查。

所有 645 次被采样的控制函数调用都正常返回，没有超过 50 ms。控制调用起点间隔 P95 各轮约 51.6～52.8 ms，最长 ON 58.4 ms / OFF 62.1 ms；OFF 仍存在少量超过 60 ms 的起点间隔，说明计算耗时缩短不等于系统调度抖动完全消失。采样窗口没有 controller 的 missed-rate 警告，也没有进展失败。

Nav2 容器平均 CPU 从单核口径 75.5% 降至 61.0%，RViz 约 40.4% 与 40.3%，GPU 均值约 54.1% 与 54.3%。本轮没有验证显著的 GPU/RViz 资源下降。只关闭 MPPI 的轨迹发布，RViz 窗口、其他图层与已有轨迹图形仍保留，因此不能把它描述为“关闭 RViz”的测试。

轨迹发布开启时约 3.09 MiB/s，关闭时为零，确认实际执行了预期分支。最终速度两组均约 20 Hz。

## 边界与恢复

测试开始时 `/cmd_vel` 没有底盘订阅者，机器人实测位姿基本固定。因此本次是使用真实传感/高程图的固定起点控制计算性能对照，不是机器人实际走完路径的成功率或制动验收。目标由测试程序主动取消，不能描述为到达终点。

可视化动态参数已经恢复 true，YAML 没有修改。随后重启导航 launch，移除临时计时钩子；保留正常的 keep_zero、初始位姿 TF 和传感器链路，结束时没有活动测试目标。

## 建议

调试阶段可保留现有可视化；需要更大 CPU/控制周期余量时，关闭 `FollowPath.visualize` 是本次已验证有效的选择。此次没有替用户永久更改默认开关。暂时保持控制 20 Hz、高程 10 Hz。
