# 优化与离线验证优先清单

日期：2026-10-18

目标：减少 Jetson 计算开销，优先保持现有高程判定逻辑；通过离线验证减少实机反复测试的时间。

本文分为两个清单。“仿真”部分指合成地图、人工轨迹、插件测试和 bag 离线验证，不要求 Gazebo、底盘或完整 controller_server。勾选表示该项已实施并完成所述验证，未勾选项仍待完成或只完成部分。

最新进展：O1、O4、O5 已完成，本地两个包已构建并通过测试。第一批平地高程评分由 40.789 ms 降至 26.213 ms；第二批高度层 0.10 m 输入地图扫描由 3.426 ms 降至 2.292 ms，对照结果一致。详见 [第一批查询优化](query_optimization_results_2026-10-18.md) 和 [第二批高度层扫描及真实 costmap 验证](height_scan_optimization_results_2026-10-18.md)。两部分收益不可直接相加。其余未勾选项仍待完成，阶段记录不代表它们已经通过。

## 一、优化清单

按推荐实施优先级排序。每次只引入一项，先通过对应验证，再继续下一项。

| 完成 | 顺序 | 优化项 | 预期作用 | 对现有逻辑的影响及验证要求 |
|---|---|---|---|---|
| [x] | O1 | 将 height_obstacle_layer 改为 Release 构建 | 消除当前未开启编译优化的开销 | 已本地构建并通过测试，保留 `-fno-fast-math`；未单独测量该项收益 |
| [ ] | O2 | 非观测阶段关闭 MPPI 轨迹可视化 | 减少消息生成、传输和显示开销 | 核心评分规则不变；需要采样轨迹观测或录包时保留 |
| [ ] | O3 | 按需关闭高度差图，降低 costmap 发布频率 | 减少可视化数据处理及发布开销 | 保持 costmap 更新频率；核对外部订阅者需求，实验录包需要的输出仍保留 |
| [x] | O4 | 每轮评分准备 elevation 矩阵访问，减少层名称查找 | 降低高频查询的固定开销 | TerrainQuery 持有快照，旧查询与新查询对照通过；范围预检和索引保护保留 |
| [x] | O5 | 用直接矩阵索引优化高程查询及高度层九点扫描 | 减少通用接口和层名查找开销 | 两部分均已完成；坐标与取整仍调用原 GridMap 接口。覆盖循环索引、轴方向、边界、NaN、非整除半径和真实 costmap 输出 |
| [ ] | O6 | 在高度层扫描前过滤可明确忽略的重复、乱序消息 | 避免无效的全图扫描 | 保留提交时复核；保持原有失效策略，不允许重复消息延长有效期 |
| [ ] | O7 | 高度层只遍历更新窗口对应的障碍 | 减少每轮遍历全部障碍点的开销 | 最终 costmap 必须一致；覆盖窗口边界、滚动地图和其他层重绘 |
| [ ] | O8 | 对前后快照做差，缩小脏区域 | 减少大范围重绘及后续膨胀开销 | 复杂度较高；必须验证障碍移除、旧区域清除、reset 和滚动地图 |
| [ ] | O9 | 评估九邻域统计预计算，供 MPPI 查询 | 将重复邻域计算移出评分内层 | 不预设为等价优化；任意位置与栅格中心采样可能不同，未知、越界、起步豁免均需保留原语义 |
| [ ] | O10 | 评估局部、全局高度层与 MPPI 共享基础统计 | 减少同一地图的重复处理 | 只考虑共享基础数据；不同模块未知策略不同，不能直接共用最终障碍标签；需核对参数、地图版本和坐标系 |
| [ ] | O11 | 必要时减少 batch_size | 减少轨迹采样与评分量 | 明确改变控制结果；仅当前面优化仍不足时考虑，需要闭环导航回归 |
| [ ] | O12 | 最后考虑减少 time_steps 或改变 model_dt | 降低预测计算量 | 会改变预测时域或时间离散，不属于保持逻辑的优化；需要重新评估导航表现 |

收益以测量结果为准。O4–O10 的最终排序可以根据耗时分布调整；不为完成清单而引入没有实际收益的复杂度。

### 推荐交叉执行顺序

1. 先完成 V1、V2、V3，获得可重复的正确性和性能基线。
2. 执行 O1–O3，每项按 V9 验证；显示和发布优化应在有相应订阅负载时比较开销。
3. 完成 V4–V6，再执行 O4–O6。
4. 完成 V7，再执行 O7–O8。
5. 根据 V3 测得的瓶颈决定是否值得做 O9–O10，结合 V4–V8 检查等价性。
6. 前述优化仍不满足需求时，再考虑 O11–O12，并安排 V10。

### 验收原则

- 保持逻辑的优化：要求离散判定、轨迹代价、失败标志及最终障碍栅格一致。浮点中间量如采用容差，不能容忍阈值判定翻转。
- 性能：同一输入、同一编译条件下比较，记录 Jetson 功耗模式、温度和后台负载；计时排除测试中的等待订阅与人为 sleep。
- 20 Hz 对应整轮控制预算 50 ms，不能将其全部分配给 HeightJumpCritic；独立评分加速不等于完整控制周期同比加速。
- 现有高度层测试主要覆盖分类与时间戳策略，尚不能代替 V7 的真实 costmap 集成验证。
- 离线一致性和性能测试能大幅减少实机工作量，但有限测试不能证明所有输入都等价，也不能替代最终并发与闭环验证。

### 现有测试运行入口

在已完成构建的工作区运行：

```bash
source /opt/ros/humble/setup.bash
source install/setup.bash
colcon test --packages-select height_jump_mppi_critic height_obstacle_layer
colcon test-result --verbose
```

纯算法测试不需要 ROS 节点；地图测试需要相关库；现有插件测试会创建最小 ROS、costmap 和 CriticManager 环境，但不需要完整控制器或仿真器。

### 独立运行入口（已新增）

```bash
source /opt/ros/humble/setup.bash
source install/setup.bash
python3 scripts/run_offline_validation.py --ros-tests --benchmark \
  --output /tmp/mppi-offline-report-001
```

每次使用新的输出目录。程序保存 Git 版本、差异、现有 CMake 缓存、逐项日志和 `report.json`；不会修改工作区的 build/install、导航配置或启动控制器。新文件尚未提交时需另外保存其内容，Git diff 不包含未跟踪文件。

不带 `--ros-tests` 时只运行可独立编译的分类和快照策略测试；不带 `--benchmark` 时不做性能测量。ROS 测试使用已有构建产物，修改源码后必须先重新构建，不能用旧二进制验证新代码。

基准输入为固定的 56,000 个位置，包含平缓地形、台阶和未知区域，预热 10 轮后统计 100 轮的 P50/P95/P99。它测量真实 evaluate 函数配合合成查询的耗时，不含 GridMap、TF、消息、完整轨迹提前退出或 MPPI 控制循环。输出中的 checksum 用于保留计算结果；测试进程的总运行时间不能当作算法耗时。

这一模式提供已有测试汇总和纯算法计时；真实地图查询测试见下一节。新旧优化差分、真实高度层集成与 bag 对照仍按上面的清单逐项建设，不能据此勾选整项 V3 或 V4。

### 真实 GridMap 查询验证与基准（第二阶段）

```bash
source /opt/ros/humble/setup.bash
source install/setup.bash
python3 scripts/run_offline_validation.py --ros-tests --benchmark --terrain-benchmark \
  --output /tmp/mppi-offline-terrain-001
```

- `--terrain-tests`：在临时目录独立构建当前 `terrain_map.cpp` 及测试程序，比较消息转换后的查询与原地图索引查询，并用独立判定过程核对九点结果。无需 ROS 节点或运行中的控制器。
- `--terrain-benchmark`：包含上述正确性测试，再测真实 GridMap 转换和九点评分；即使正确性测试失败，仍单独测内部位置的基准，整体报告保持失败。
- 覆盖平地、台阶、随机高度与缺测、全未知；0.05/0.10/0.13 m 分辨率；非正方形地图、滚动索引、精确边界及相邻浮点数；0.10/0.17 m 采样半径、两种未知策略和起步豁免。
- 计时输入为 7 × 5 m、0.10 m 分辨率地图，固定种子的 1000 × 56 个随机位置，包含轨迹提前拒绝。随机位置不满足运动模型，测试不包含 TF、消息传输、完整 MPPI 或高度层更新。地图转换与评分分别计时，预热 10 轮、测量 100 轮。
- 保存源文件 SHA256、独立测试二进制 SHA256、编译参数和编译器版本。哈希用于追踪版本，不代替保存未提交的源文件；运行过程中不要编辑参与测试的源码。

这是当前实现与参考计算的对照，尚无优化版，因此不能称为新旧优化等价性验证。V3 已覆盖部分真实地图评分，V4/V7/V8 仍未完成。

**本机发现并修复的边界问题：** 在 0.13 m 分辨率的极近地图边缘位置，GridMap 的 `getIndex()` 可能报告成功，但返回等于地图尺寸的索引。例如尺寸为 54 × 38 时返回 `(54,19)` 或 `(27,38)`。最初对照程序将其报为失败；后续已通过独立回归测试复现，并在 `TerrainSnapshot::query()` 读取前增加索引范围保护，非法索引按 Outside 处理。对照测试保留异常索引计数，要求实际查询也返回 Outside，没有跳过问题输入。修复前记录和修复后结果分别保留，详见 [边界修复验证](boundary_fix_verification_2026-10-18.md)。不能用这一发现断定当前 0.10 m 配置必然触发，也不能据有限测试保证所有输入都无问题。

独立构建还观察到本机 OpenCV 4.5d 与 4.10 的链接冲突警告，保存在构建日志中；这是环境风险，当前未改动依赖。执行测试成功不等于已经排除此风险。
