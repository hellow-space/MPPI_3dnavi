# 高程图四场景定性验证流程

## 本轮目标

本轮只验证系统的基本工作逻辑，不做精度、误差、成功率等量化评价。

**每个场景录一包，只需提供场景名称和对应的 rosbag 文件夹。** 不需要尺寸、照片、现场备注或额外测量。

例如：平地 rosbag、绕障 rosbag、上坡 rosbag、楼梯 rosbag。上坡或下坡按实际测试的方向命名即可，不要求两个方向都做。

## 一、统一操作流程

1. 找到对应场景，将机器人放到起点，先站起来。
2. 启动平时使用的定位、高程图和高程导航，等待机器人姿态与 RViz 显示稳定。
3. 检查录制所需话题：

   ```bash
   cd /home/nvidia/MPPI_3dnavi
   bash nav_experiment_toolkit/scripts/check_before_record.sh elevation
   ```

   如果提示核心话题缺失，先处理再录制。

4. 开启统一录包：

   ```bash
   bash nav_experiment_toolkit/scripts/record_nav_elevation.sh
   ```

5. 等录制开始后，原地停约 10 秒。
6. 执行本场景的动作。
7. 动作结束后停约 10 秒，在录包终端按一次 `Ctrl+C`，等待录制结束。
8. 保留整个 bag 文件夹，包括 `metadata.yaml` 和数据文件。

每个场景先做一次即可。保持同一套参数，使用平时已经验证稳定的速度和控制方式。斜坡、楼梯选择机器人已经确认可以通过的场地。

## 二、四个场景怎么做、验证什么

### 1. 平地

**执行：** 在平整地面上，让机器人正常向前走一段，录一包。

- [ ] 完成平地录包。

**包内验证逻辑：**

- 机器人移动时，高程图是否持续更新并覆盖新看到的地面。
- 同一片地面的高程显示是否基本连贯，有没有明显跳变、漂移或大片异常消失。
- 平地上是否出现明显异常的高度差障碍。

**本项回答：** 平地运动过程中，高程图更新和地面表达是否基本正常。

### 2. 绕障

**执行：** 找一个明显高于当前高度差阈值的稳定障碍物，旁边留出绕行空间。将导航目标设在障碍后方，让机器人自行绕行，录一包。

- [ ] 完成绕障录包。

**包内验证逻辑：**

- 点云和高程图中是否出现对应的障碍结构。
- 高度差图中是否出现对应的高度突变。
- 代价地图中是否出现对应的障碍区域。
- 路径、机器人运动和速度命令是否表现出避让，或在无法通过时停止。

按下面的顺序检查：

```text
看到障碍 → 高程出现突变 → 形成障碍代价 → 路径/运动作出响应
```

**本项回答：** 高程信息到障碍表达、再到导航响应的链路是否基本正常。

如果只看到机器人绕行，但看不到对应的高程和障碍代价变化，不直接认定是高程模块促成了绕障。

### 3. 斜坡

**执行：** 找一段可通过的斜坡，让机器人从坡前平地经过坡面，到另一端平地，录一包。按实际方向标为“上坡”或“下坡”。

- [ ] 完成斜坡录包。

**包内验证逻辑：**

- 点云和高程图中是否呈现连续升高或降低的坡面。
- 经过坡底、坡面和坡顶时，高程图是否保持连贯更新。
- 机器人姿态变化时，地图是否出现明显整体跳变、异常倾斜变化或大面积缺失。
- 高度差图、代价地图和运动数据是否出现对应变化，有没有异常阻断或停滞。

**本项回答：** 经过斜坡时，高程图能否持续表达坡面，相关判定和运动是否存在明显异常。

不根据这一包判断坡度测得有多准，也不推断机器人的最大爬坡能力。

### 4. 楼梯

**执行：** 找一段已经确认可以通过的楼梯，按平时已经验证过的控制方式通过，录一包。按实际方向标为“上楼梯”或“下楼梯”。

- [ ] 完成楼梯录包。

**包内验证逻辑：**

- 点云和高程图中是否能看到可见台阶的分层或阶跃结构。
- 移动过程中，台阶结构是否随新观测持续更新。
- 台阶边缘在高度差图和代价地图中是否产生相应变化。
- 是否出现明显拖影、结构跳变、缺测，以及对应的运动中断。

**本项回答：** 楼梯场景下，高程图能否表达可见台阶并持续更新，相关判定和运动是否存在明显异常。

不要求所有台阶都显示完整；对被遮挡或没有观测到的区域，标记为无法判断，不把缺测直接当作平地。

## 三、只凭 rosbag 怎么给结论

收到数据后，先确认相关话题确实有消息、时间范围覆盖动作过程，再回放检查上述逻辑。

每个场景只给出：

- **观察到正常现象：** 包内能看到预期的更新、地形表达或导航响应。
- **观察到异常现象：** 指明异常发生在哪一段、哪一环节。
- **数据不足，无法判断：** 关键话题缺失、观测被遮挡或包内无法确认的事项，明确说明。

仅凭包内数据，不宣称高度或坡度准确，也不将命令速度等同于实际运动。机器人运动结合 TF/里程计查看；任务完成结合实际记录到的任务状态查看。

如果包内没有足够信息确认自主导航任务，就只评价地形更新和记录到的运动，不宣称完成了自主通过或无碰撞验证。

## 四、交付方式

只提供场景与 bag 的对应关系即可：

```text
平地：bag 文件夹路径
绕障：bag 文件夹路径
上坡或下坡：bag 文件夹路径
上楼梯或下楼梯：bag 文件夹路径
```

默认录包保存位置：

```text
/home/nvidia/MPPI_3dnavi/nav_experiment_toolkit/bags/nav_elevation/
```

不需要额外填写实验表、拍照、测量尺寸或自行分析。完成一个场景也可以先提供对应的包。
